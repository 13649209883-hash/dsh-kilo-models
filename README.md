# dsh-kilo-models

把 Kilo 免费模型名册做成设置里的按钮：点一下就能更新列表、探测可用性、分好等级，再把结果更新模型选择列表。

## 功能

### 一、点一下更新模型列表

设置里多了「Kilo 模型」一页，有自己的界面。点「检测可用性」，就去 Kilo 拉一次全量清单，
筛出免费的那批，然后挨个发一句 `Reply with exactly: OK` 真测一遍（并发 4 个，每个最多等 20 秒）。

- 表格四列：分类/分 · 模型（名称、id、发布日、能力标签）· 连通性（可用 968ms / 限流 HTTP 429 / 具体错误）· 到期日。
  宽度压在面板内，不用横向拖动；鼠标悬停能看到上下文、评分依据、完整报错。
- 只想更新清单、不想花额度，点「只更新列表」，不调推理端点。
- 勾选想要的模型，点「更新模型选择列表」，写进 `cordis.patch.yml` 的 `llm-pi-ai.providers.kilo.models`，
  其余文本一字不动，写前自动备份。

### 二、先按上下文大小分类，再各自内部评分

上下文大小不再参与打分，它只决定**分到哪一类**：

| 分类 | 上下文范围 |
|:--|:--|
| ≥1M | 100 万 token 及以上 |
| 512K–1M | 51.2 万到 100 万 |
| 256K–512K | 25.6 万到 51.2 万 |
| 128K–256K | 12.8 万到 25.6 万 |
| <128K | 12.8 万以下 |

同一类内部的「分」就是**排行榜分**（0–100），不再掺上下文、也不掺新鲜度：

```
分数 = 排行榜分
       查不到榜单分 → 分数显示「—」，排在本组末尾
```

榜单分来自联网搜索（`ctx.web.search`）：现查一次排行榜，把各家 Elo 折算成 0–100；查不到就用
内置快照 `data/rankings.json`（人工整理的家族参考分）。点「按排行榜评分」只重算分数，不重拉清单。

分组之后有两种排法，标签页右侧切开：

| 排序 | 规则 |
|:--|:--|
| 按分数 | 组内分数从高到低；**没有榜单分的排到本组最后**（它们只有「新鲜度 + 基线」的折算分，和真榜单分不可比） |
| 按发布时间 | 组内按模型发布日从新到旧，缺发布日期的沉底 |

行里带「发布 YYYY-MM-DD」，两种排法都能一眼看出新旧。检测失败的记「不可用」，整体沉到列表底部；
429 / 408 / 5xx 记「限流」，留在原分类里。

### 三、选模型的时候就能看到重要标签

在模型的菜单里，名字后面直接跟一小段灰色文字：

| 文字 | 意思 |
|:--|:--|
| 视觉 / 视频 / 音频 | 能读这类输入 |
| 工具 | 支持 tool calling |
| 推理 | 有 thinking 档 |
| 到期 | 30 天内免费额度失效 |

最多显示 4 个，多出来的记 `+N`，鼠标悬停看全。之前用的是 emoji 图标，不直观也没有地方查含义，
所以改成了文字。

### 四、可用模型和完整清单在同一页，两个标签页切换

「Kilo 模型」这一页顶部有两个标签：

- **全部模型**：完整表格，带勾选框、等级、分数、上下文、标签、依据、探活、到期，勾好可以更新模型选择列表。
- **可用模型**：只列探活通过的，卡片式，带等级、分数、上下文、标签，可以复制模型 id。

不用在两个设置页面之间来回跳。

## 安装

1. 克隆：

   ```powershell
   git clone git@github.com:13649209883-hash/dsh-kilo-models.git E:\deepseek\plugins\dsh-kilo-models
   ```

2. 链接进 DSH profile（junction，改源码不用重拷）：

   ```powershell
   New-Item -ItemType Junction `
     -Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-kilo-models" `
     -Target "E:\deepseek\plugins\dsh-kilo-models"
   ```

3. 在 `~/.dsh/profiles/desktop/cordis.patch.yml` 末尾加：

   ```yaml
   - insert:
       - id: kilo-models
         name: dsh-kilo-models
   ```

4. 重启 DSH，刷新页面（Ctrl+F5）。设置里会出现「Kilo 模型」一页，顶部是「全部模型 / 可用模型」两个标签，
   右侧是「按分数 / 按发布时间」的排序切换。

前提：`cordis.patch.yml` 里已经有 `llm-pi-ai` 的 Kilo 路由（`providers.kilo`），
并且 `KILO_API_KEY` 在环境变量或 `~/.dsh/.credentials.yaml` 里。插件不创建 provider，只维护它的 `models`。

## 注意

- Kilo 免费池会把 prompt 记为可训练（`mayTrainOnYourPrompts: true`），别喂敏感内容。
- 「按排行榜评分」每次消耗一个模型轮次，不想花就取消勾选，用内置快照。
- 榜单分是家族级的近似值，用来排序分档，不是严格评测。
